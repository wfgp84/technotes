1.1稀疏相似度 — 问题

给一堆集合/文档，任意两个的相似度都接近 0（几乎不相交），要高效算出所有 sim > 0 的对。LeetCode 面试题 17.26 就是这类问题的典型。

模型

  • 输入：N 个集合 D0, D1, …, DN-1，每个含互不重复的元素。
  • 相似度：Jaccard J(A, B) = |A ∩ B| / |A ∪ B|。
  • 稀疏假设：J(Di, Dj) ≈ 0 对大多数 (i, j) 成立。
  • 输出：所有 J > 0 的 (i, j) 及 J 值。

为什么不能 O(N²)

  • 两两比较：外层 C(N,2) 对，内层每对求交集 O(K)。
  • N = 104 时约 5×107 对，109 级操作 — 太慢。
  • 更糟：稀疏假设下 99% 的对返回 0，全是浪费。

1.2倒排索引法 — 从 "词" 出发

只有共享至少一个元素的文档对才可能有正相似度。用倒排索引把 "文档 → 词" 反转成 "词 → 文档"。

三步走

  1. 建倒排索引 word → [doc_ids] — O(N·K)
  2. 枚举 posting list 内的对，给 intersect[(i,j)] 计数 +1
  3. 遍历非零 intersect，用 |Di| + |Dj| - c 得到并集大小，算 Jaccard
核心洞察： 第 2 步的工作量是 Σw f(w)²，其中 f(w) 是词 w 出现在多少个文档里。 稀疏 → 每个 f(w) 普遍很小 → Σ f(w)² << N²。这就是稀疏假设的红利。

倒排索引长这样

// 正排（原始）:
doc 0: [apple, banana, cherry]
doc 1: [banana, date]
doc 2: [apple, cherry, elderberry]

// 倒排:
apple      -> [0, 2]
banana     -> [0, 1]
cherry     -> [0, 2]
date       -> [1]
elderberry -> [2]

按 doc_id 升序 push_back，每个 posting list 天然升序 → (i, j) 里 i < j 天然成立，不需要 swap。

1.3C++ / Python 实现

C++

#include <vector>
#include <string>
#include <unordered_map>
#include <map>
#include <cstdio>

std::vector<std::string>
computeSimilarities(std::vector<std::vector<int>>& docs) {
    const int n = (int)docs.size();

    // 1) 倒排索引：word -> [doc_id 升序]
    std::unordered_map<int, std::vector<int>> inv;
    for (int i = 0; i < n; ++i) {
        if (docs[i].empty()) continue;              // 忽略空文档
        for (int w : docs[i]) inv[w].push_back(i);
    }

    // 2) 用 std::map 保证输出天然按 (i,j) 升序
    std::map<std::pair<int,int>, int> inter;
    for (auto& kv : inv) {
        const auto& v = kv.second;
        for (size_t a = 0; a + 1 < v.size(); ++a)
            for (size_t b = a + 1; b < v.size(); ++b)
                ++inter[{v[a], v[b]}];
    }

    // 3) Jaccard 公式并格式化
    std::vector<std::string> out;
    out.reserve(inter.size());
    for (auto& kv : inter) {
        int i = kv.first.first, j = kv.first.second, c = kv.second;
        double sim = (double)c
                   / (docs[i].size() + docs[j].size() - c);
        char buf[64];
        std::snprintf(buf, sizeof(buf), "%d,%d: %.4f", i, j, sim);
        out.emplace_back(buf);
    }
    return out;
}

Python

from collections import defaultdict

def computeSimilarities(docs):
    inv = defaultdict(list)
    for i, d in enumerate(docs):
        for w in d:
            inv[w].append(i)

    inter = defaultdict(int)
    for indices in inv.values():
        for a in range(len(indices)):
            for b in range(a + 1, len(indices)):
                inter[(indices[a], indices[b])] += 1

    result = sorted(
        (i, j, c / (len(docs[i]) + len(docs[j]) - c))
        for (i, j), c in inter.items()
    )
    return [f"{i},{j}: {s:.4f}" for i, j, s in result]

关键行剖析: ++inter[{v[a], v[b]}]

  1. {v[a], v[b]} — 花括号初始化，构造 std::pair<int,int>。
  2. inter[key] — 存在则返回引用；不存在则自动插入，值默认为 int() = 0，返回对新值的引用。
  3. ++ — 把引用指向的值加 1。

一行完成 "初始化 + 累加"。注意副作用：operator[] 会插入默认值，如果只想查询用 .find()。

复杂度

阶段时间空间
建倒排索引O(N·K)O(N·K)
交集计数O(Σ f(w)²)O(P)
输出O(P)O(P)

K = 平均文档大小，f(w) = 词 w 的文档频次，P = sim > 0 的对数。

1.4优化 & 大规模 MinHash

换成 unordered_map + 自定义哈希 (常数快 3-5×)

struct PairHash {
    size_t operator()(long long k) const noexcept {
        k ^= k >> 33; k *= 0xff51afd7ed558ccdULL;
        k ^= k >> 33; k *= 0xc4ceb9fe1a85ec53ULL;
        k ^= k >> 33; return (size_t)k;
    }
};
std::unordered_map<long long, int, PairHash> inter;

for (const auto& [term, v] : inv) {
    for (size_t a = 0; a + 1 < v.size(); ++a) {
        long long lo = (long long)v[a] << 32;    // 外提
        for (size_t b = a + 1; b < v.size(); ++b)
            ++inter[lo | (unsigned)v[b]];
    }
}
停用词陷阱： 如果某个词几乎出现在所有文档里（"停用词"），f(w) ≈ N，那 f(w)² ≈ N² 直接退化。 预处理时按 df 过滤最常见的 5% 词是标准做法。

大规模: MinHash + LSH

当元素域巨大（十亿级）或 Σ f(w)² 也爆时，切换到近似算法：

MinHash

  • 用 k 个哈希函数，每个函数对文档所有元素取哈希，取最小值。
  • 每个文档得到长度为 k 的 "签名"。
  • 两文档签名中同位置相等的比例是 Jaccard 的无偏估计。
  • 空间：O(N·k)；k = 128 通常已足够准。

LSH (Locality-Sensitive Hashing)

  • 把 k 长签名切成 b 段，每段 r 行。
  • 只要有一段完全相等，就当作 "候选对"。
  • 概率放大：调 (b, r) 让 sim > τ 的对几乎必被抓到，sim << τ 的对几乎不被抓到。
  • 最后只对候选对精确计算。

开源实现: Python datasketch；C++ 有若干独立库。Google/Bing 网页去重用的就是这一套。

2.1红黑树 — 5 条不变量

Red-Black Tree 是一种自平衡二叉搜索树。std::map / std::set / Java TreeMap / Linux CFS 调度器 / epoll / nginx timer 都用它。

是什么

一棵 BST，每个节点额外带一个颜色：红 或 黑。通过 5 条不变量保证 树高 ≤ 2·log₂(N+1)，所有操作最坏 O(log N)。

5 条 property

  1. 每个节点非红即黑。
  2. 根节点是黑。
  3. 每个叶子（NIL 空节点）是黑。
  4. 红色节点的两个孩子都是黑（no red-red）。
  5. 从任一节点到其所有后代 NIL 的路径上，黑色节点数量相同（黑高一致）。
这五条一起保证：从根到叶最长路径 ≤ 最短路径的 2 倍。因为最短路径全黑，最长路径必是红黑交替，长度顶多 2 倍。

一个合法红黑树的例子

每条根 → NIL 路径上恰好 2 个黑节点（含根）；无红-红父子；根黑。

2.2为什么 std::map 用红黑树

vs 其他自平衡树

树平衡严格性查找插入/删除旋转次数额外空间
BST无O(N) 最坏O(N) 最坏0少
AVL严格（高差 ≤1）快（更矮）稍慢多+1 int/node
红黑宽松（≤2 倍）略慢快少+1 bit/node
Splay摊还O(log N) 摊还O(log N) 摊还每次都调少
B-Tree严格O(log N)O(log N)—高扇出

std::map 用到的性质

  • 有序遍历：begin() → end() 是升序。前面 sparse-similarity 里 inter 输出天然按 (i, j) 排序的原因。
  • lower_bound / upper_bound：O(log N)，哈希做不到。
  • 迭代器稳定：插入/删除不 invalidate 其它迭代器（unordered_map rehash 会）。
  • 前驱 / 后继：std::prev(it) / std::next(it) 是 O(1) 摊还。
常数大的代价： 每个节点至少 3 个指针 + 键值对 + 1 bit 颜色，对齐后 40-56 字节。O(log N) 次跳指针，cache locality 差。 这就是 std::unordered_map（哈希）通常快 3-5× 的原因。

2.3旋转 + 重染色

修复不变量只需要两种操作：旋转（改结构）和 重染色（只改颜色）。

左旋（以 x 为轴，x 的右子 y 上位）

    x                       y
   / \                     / \
  a   y      -左旋->      x   c
     / \                 / \
    b   c               a   b
void rotateLeft(Node* x) {
    Node* y = x->right;
    x->right = y->left;
    if (y->left) y->left->parent = x;
    y->parent = x->parent;
    if (!x->parent) root = y;
    else if (x == x->parent->left) x->parent->left = y;
    else                          x->parent->right = y;
    y->left = x;
    x->parent = y;
}

右旋完全对称。旋转是 O(1)，只改动几个指针。

2.4插入的 4 个 case

新节点按 BST 规则插入，涂 红色（保证不破坏黑高）。若父节点也是红，进入修复。

记号：z = 新节点，p = z 的父，g = z 的祖父，u = z 的叔（p 的兄弟）。

Case条件动作
1p 是黑完成，什么都不做。
2p 红, u 红p 和 u 涂黑；g 涂红；把 g 当作新的 z 递归修复（红色向上冒泡）。
3p 红, u 黑, z 是 "内侧" 孩子（LR / RL）对 p 做旋转，转成 Case 4。
4p 红, u 黑, z 是 "外侧" 孩子（LL / RR）p 涂黑, g 涂红, 对 g 反向旋转。完成。

Case 4 图示（LL）

P 涂黑, G 涂红, 对 G 右旋。

fixup 骨架

void insertFixup(Node* z) {
    while (z->parent && z->parent->color == RED) {
        Node* g = z->parent->parent;
        if (z->parent == g->left) {
            Node* u = g->right;
            if (u && u->color == RED) {           // Case 2
                z->parent->color = BLACK;
                u->color = BLACK;
                g->color = RED;
                z = g;                             // 冒泡向上
            } else {
                if (z == z->parent->right) {      // Case 3
                    z = z->parent;
                    rotateLeft(z);
                }
                z->parent->color = BLACK;         // Case 4
                g->color = RED;
                rotateRight(g);
            }
        } else {
            // 对称：left/right 互换
        }
    }
    root->color = BLACK;                           // 保证 property 2
}

最多向上冒泡 O(log N) 次，最多 2 次旋转。

2.5删除概览

删除本身用标准 BST 后继替换。真正麻烦的是删了一个黑节点后某条路径少一个黑，产生 "doubly-black" 节点。修复看兄弟节点 s 和它的孩子，同样分 4 个 case（对称一共 8 个），用旋转 + 重染色把 "黑亏损" 消化掉或向上传。

  • 被删节点是红 → 直接删，什么都不用做。
  • 被删节点是黑，替代者是红 → 把替代者涂黑。
  • 被删节点是黑，替代者也是黑 → 进入 fixup，4 个 case。

最坏 O(log N) 时间，旋转不超过 3 次。

何时用/不用

  • 需要顺序 + 范围查询 → std::map（红黑）
  • 只需等值查询 → std::unordered_map（哈希）快 3-5×
  • 只读大数据 → 排序 vector + std::lower_bound，比 map 快得多
  • 需要范围查询 + 稠密数据 → 分块 / segment tree / 有序 vector
一句话记忆红黑树： BST + 1 bit 颜色 + 5 条不变量，通过旋转和重染色保证树高不超过 2·log₂(N+1)，插入/删除的修复代价是常数级 O(1) 结构改动。
